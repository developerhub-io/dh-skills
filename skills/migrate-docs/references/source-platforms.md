# Source platforms

How to recognise each docs tool, where its structure lives, and how its syntax maps to
DeveloperHub Markdoc. The general rules (which callout type, how tabs become code
groups, what to do with raw HTML) are in [`conversion-rules.md`](conversion-rules.md);
this file gives each tool's spelling of them and its traps.

Read config files as text. Several of them are code (`docusaurus.config.js`,
`sidebars.ts`, `conf.py`, `_meta.ts`, `astro.config.mjs`); do not execute them. Most
navigation in them is a literal you can read. When it is truly computed, ask before
running anything.

`package.json` dependencies confirm most JavaScript tools. A repository can hold more
than one tool (a Docusaurus site plus a Sphinx API site): treat each as its own source
and ask how they fit together.

## Docusaurus

**Content.** `docs/` by default, or the `path` of each docs plugin instance in
`docusaurus.config.*` (several instances usually mean several documentations). Pages
are `.md` and `.mdx`. Files and folders starting with `_` are partials, not pages.
`static/` holds files served from the site root (`/img/x.png`). `blog/` is the blog.
`src/pages/` holds standalone pages (usually the React landing page).

**Navigation.** `sidebars.{js,ts}`: each exported sidebar is a list of items:
`'doc-id'`, `{type: 'doc', id, label}`, `{type: 'category', label, items, link,
collapsed}`, `{type: 'link', label, href}`, `{type: 'html'}`,
`{type: 'autogenerated', dirName}`. A category whose `link` is `{type: 'doc', id}` is
a parent page; one with `{type: 'generated-index'}` is a category (add an
`{% index-list %}` page only if the customer wants the index). Autogenerated parts
follow the folder tree, ordered by `sidebar_position` frontmatter, then
`_category_.json` / `_category_.yml` (`label`, `position`, `link`, `collapsed`), then
number prefixes (`01-intro.md`, stripped from the id). Several sidebars wired to
navbar items (`type: 'docSidebar'`) are separate documentations, in navbar order.

**Doc ids and URLs.** The id is the path without extension and number prefixes, or
the `id` frontmatter. URLs are `/<routeBasePath>/<id or slug>` (default
`/docs/...`); the `slug` frontmatter overrides it.

**Versions.** `versions.json` (newest first), `versioned_docs/version-<v>/`,
`versioned_sidebars/version-<v>-sidebars.json`. The current `docs/` folder is the
"next" version: ask whether it is released.

**Languages.** `i18n/<locale>/docusaurus-plugin-content-docs/current/`.

**Frontmatter.** `title`, `sidebar_label` → `index_title`, `description`,
`keywords`, `tags`; `sidebar_position` → order; `slug`, `id` → path map;
`draft`, `unlisted`; `hide_title`, `displayed_sidebar`, `pagination_*` dropped.

| Docusaurus | DeveloperHub |
|---|---|
| `:::note`, `:::tip`, `:::info`, `:::warning`, `:::caution`, `:::danger` (title as `:::note[Title]` or `:::note Title`), `<Admonition type>` | callout |
| `<Tabs groupId>` + `<TabItem value label default>` | tabs, or a code group when every tab is one fence |
| `` ```js title="x" showLineNumbers {1,4-6} `` | fence with `title`, `showLineNumbers=true`, `highlightLines` |
| `// highlight-next-line`, `// highlight-start` / `-end` | `highlightLines`, comments removed |
| `import X from '@site/…/_x.mdx'` + `<X />` | the partial, inlined or a synced block |
| `import CodeBlock from '@theme/CodeBlock'` + `<CodeBlock>{Source}</CodeBlock>` with `!!raw-loader!` | fence with the file inlined |
| `<details><summary>` | accordion |
| `<DocCardList />` | `{% index-list /%}` |
| `<img src={require('./x.png').default} />`, `useBaseUrl('/img/x.png')`, `<ThemedImage>` | image |
| `## Title {#custom-id}` | heading without the id; retarget links |
| `{/* comment */}`, `<head>` blocks | removed |
| `export const` values used in the page | inlined values |
| `` ```mermaid `` | see diagrams in the general rules |

Traps: `.mdx` links (`./setup.mdx`) and links without extension both resolve through
the path map; `index.md`, `README.md` or a file named after its folder is that
category's page.

## MkDocs and Material for MkDocs

**Content.** `docs_dir` in `mkdocs.yml` (default `docs/`). The `markdown_extensions`
list tells you which syntaxes to expect.

**Navigation.** `nav:` in `mkdocs.yml`: a list of `Title: path.md`, `path.md`,
`Section: [ ... ]` and external `Title: https://…`. Without `nav:`, the folder tree in
alphabetical order. Plugins change that: `awesome-pages` (`.pages` files with `title`,
`nav`, `arrange`), `literate-nav` (`SUMMARY.md`). With the `navigation.indexes`
feature, a section's `index.md` is the section's page (a parent page). With
`navigation.tabs`, the top-level sections are tabs (documentations).

**URLs.** `use_directory_urls: true` (default) gives `/section/page/`; false gives
`/section/page.html`.

**Versions.** `mike` keeps each version as a separate build on the `gh-pages`
branch; the sources are the Git tags or branches each version was built from. Ask
which, then read the docs folder at each ref.

**Languages.** `mkdocs-static-i18n`: `docs/<lang>/` folders or `page.<lang>.md`
suffixes.

**Frontmatter.** `title`, `description`, `tags`; `hide`, `icon`, `status`,
`search` dropped.

| MkDocs / Material | DeveloperHub |
|---|---|
| `!!! note "Title"` + body indented 4 spaces (types: note, abstract, info, tip, success, question, warning, failure, danger, bug, example, quote); `!!! note ""` hides the title | callout |
| `??? note "Title"` / `???+ note` | accordion (closed / `open=true`) |
| `=== "Tab"` + indented body | tabs, or a code group |
| `` ```py title="x" linenums="1" hl_lines="2 3" `` | fence annotations |
| `--8<-- "file"` (snippets) | include |
| `# (1)!` code annotations + `{ .annotate }` | markers removed, the list after the block |
| `<div class="grid cards" markdown>` + list | cards |
| `{ width="300" }`, `{ align=left }`, `{ .class }`, `{ #id }` (attr_list) | `width=` / `align=`; classes and ids removed |
| `:material-check:`, `:fontawesome-solid-x:`, `:octicons-x-16:`; `:smile:` | icon or nothing; emoji character |
| `++ctrl+alt+del++` | `{% key key="Ctrl+Alt+Del" /%}` |
| `*[HTML]: HyperText Markup Language` | definitions removed |
| `==mark==`, `^^ins^^`, `H~2~O`, `[^1]`, `- [x]` | see small inline constructs |
| `<figure markdown>` + image + `<figcaption>` | image with caption |
| `{{ var }}` (mkdocs-macros) | `%VAR%` variables |
| `[TOC]` | removed |
| `::: package.module` with indented options (mkdocstrings), `::: module.Class` + `:docstring:` / `:members:` (mkautodoc) | generated library reference: see the API reference question in SKILL.md; the text is not in the source |

Traps:

- Python-Markdown nests list content by 4 spaces. Re-indent nested blocks to sit under
  the list item's text (2 spaces after `-`, 3 after `1.`), or they fall out of the
  list.
- The reverse also happens: a list the old site showed flat because its items were
  indented by only 2 spaces nests in DeveloperHub. Check what the published page
  shows, keep that, and log it.
- `theme.custom_dir` overrides (extra header links, banners, footers) are branding:
  list them for the app.

## Sphinx and Read the Docs

**Content.** `source/` or `docs/` next to `conf.py`. reStructuredText (`.rst`),
Markdown through MyST (`myst_parser` in `extensions`), notebooks (`nbsphinx`,
`myst_nb`). Jupyter Book uses `_toc.yml` and `_config.yml`.

**Navigation.** `.. toctree::` directives, starting from `index.rst` (the
`root_doc`): each entry is a document path; a document with its own toctree is a
parent page; `:caption:` names a category or label; `:hidden:` toctrees still define
the navigation. Jupyter Book: `_toc.yml` (`parts` → categories, `chapters` and
`sections` → pages).

**Versions.** On Read the Docs, versions are Git branches and tags. Ask which.

**Converting RST.** RST is not Markdown. If `pandoc` is available, convert each file
with `pandoc -f rst -t gfm --wrap=none`, then handle what pandoc leaves as generic
blocks, and turn any indented code blocks it writes into fences. Build the label map first (every `.. _label:` and the heading after it), since
`:ref:` targets live in other files. Heading levels in RST come from the order the
underline styles first appear in each file.

**autodoc.** `.. automodule::`, `.. autoclass::`, `.. autofunction::` and
`autosummary` generate pages from Python code at build time; the source does not
contain that text. Options: convert the published site's API pages
([`crawling.md`](crawling.md); the default), build the docs and convert the built
HTML (this runs the project's code: ask first), or leave them out.

| Sphinx / MyST | DeveloperHub |
|---|---|
| `.. note::`, `.. tip::`, `.. hint::`, `.. important::`, `.. warning::`, `.. caution::`, `.. attention::`, `.. danger::`, `.. error::`, `.. seealso::`, `.. admonition:: Title`; MyST `` ```{note} `` and `:::{note}` | callout |
| `.. versionadded:: 2.1`, `.. versionchanged::`, `.. deprecated::` | callout, `info` / `warning`, the version in the title |
| `.. code-block:: python` + `:caption:` `:linenos:` `:emphasize-lines:`; `::` literal blocks | fence |
| `.. literalinclude:: file` + `:lines:` `:start-after:` `:pyobject:` | fence with the file content |
| `.. image::`, `.. figure::` + `:width:` + caption | image |
| `` `text <https://…>`_ ``, `` :doc:`path` ``, `` :ref:`label` ``, MyST `` {ref}`label` `` | links through the path map |
| `.. include::` | include |
| `\|name\|` with `.. \|name\| replace:: value`, `rst_epilog` | `%NAME%` variables |
| `.. tabs::` (sphinx-tabs), `.. tab-set::` / `.. tab-item::` (sphinx-design) | tabs |
| `.. dropdown::` | accordion |
| `.. grid::` + `.. grid-item-card::`, `.. card::` | cards |
| `.. list-table::`, `.. csv-table::`, grid and simple tables | tables |
| `.. math::`, `` :math:`…` `` | math |
| `.. only:: html` | the HTML branch |
| `:param x:`, `:returns:` field lists | field table |
| notebook cells | markdown cells → prose, code cells → fences, outputs → fences or images |
| `.. toctree::`, `.. contents::` | removed after reading the navigation |

## GitBook

**Content.** `root:` in `.gitbook.yaml` (default: the repository root). The root
`README.md` is the space's first page. Images live in `.gitbook/assets/`, often with
spaces in their names.

**Navigation.** `SUMMARY.md`: `## Group` headings are categories (or labels); the
nested list `* [Title](path.md)` gives the pages and their nesting; a folder's
`README.md` is the page for that list item. A GitBook site with several spaces
(site sections, variants) arrives as several repos or exports: sections usually map
to documentations, variants to versions. Ask.

**Redirects.** `redirects:` in `.gitbook.yaml` (old path → file): carry them into
`redirects.txt` as well.

**Frontmatter.** `description` → `description` (GitBook shows it as a subtitle);
`icon` (a FontAwesome name) → the nav entry's `icon:` when it exists in the Free set;
`hidden: true` → `listed: false`; `layout`, `cover`, `coverY` dropped.

**GitBook's blocks are `{% … %}` tags that DeveloperHub does not have.** Every one
must be converted: left alone, each is an unknown tag that renders as nothing, and the
unpaired `{% end… %}` tags can swallow the rest of the page.

| GitBook | DeveloperHub |
|---|---|
| `{% hint style="info\|success\|warning\|danger" %}` … `{% endhint %}` | callout `info` / `success` / `warning` / `error` |
| `{% tabs %}` `{% tab title="x" %}` … `{% endtab %}` `{% endtabs %}` | `{% tabs %}` / `{% tab title="x" %}` closed with `{% /tab %}` / `{% /tabs %}` |
| `{% code title="x" lineNumbers="true" overflow="wrap" %}` + fence + `{% endcode %}` | the fence with `title`, `showLineNumbers=true` |
| `{% embed url="…" %}` (optionally a caption and `{% endembed %}`) | video for YouTube, Vimeo, Loom; otherwise a card or a link |
| `{% content-ref url="x.md" %}[x](x.md){% endcontent-ref %}` | a card or a plain link |
| `{% file src="…" %}caption{% endfile %}` | a link to the file's new home (only images are uploaded) |
| `{% stepper %}` `{% step %}` … `{% endstep %}` `{% endstepper %}` | ordered list steps |
| `{% columns %}` `{% column %}` | the columns stacked, or cards |
| `{% include "../.gitbook/includes/x.md" %}` | synced block or inline |
| `{% openapi src="…" path="/x" method="get" %}`, `{% swagger %}` | the spec as an API reference; a link to it on the page |
| `<figure><img src="…" alt><figcaption><p>…</p></figcaption></figure>` | image with caption |
| `<table data-view="cards">` with `data-card-target` | cards |
| `<details><summary>` | accordion |
| `<mark style="color:…">`, `<a class="button primary">`, `<i class="fa-x">` | text, link, icon |
| `$$…$$` | math |

## Mintlify

**Content.** `docs.json` (current) or `mint.json` (legacy). Pages are `.mdx`
anywhere in the tree; folders carry no meaning. `snippets/` holds reusable MDX.
Images are referenced from the repository root (`/images/x.png`).

**Navigation.** In `docs.json`, `navigation` nests, outermost first:
products → languages → versions → tabs → dropdowns → anchors → groups → pages, and any
level can be the top. A group has `group` (title), `pages` (page paths or nested
groups), `icon`, `root` (the group's own page), `expanded`, `hidden`. Page paths are
extension-less and relative to the repository root. `navigation.global.anchors` are
site-wide links (top navigation). `mint.json` has `navigation` as a list of
`{group, pages}`, with `tabs` and `anchors` matched by URL prefix.

**Mapping.** Versions → versions. The first division below versions (tabs, else
dropdowns, else anchors that hold pages, plus products) → documentations; a product
with its own tabs → `Product - Tab` documentations; none of these → one
documentation. Groups → categories, nested. `group.root` → that group becomes a
parent page. Anchors inside the navigation that only hold an `href` → `link:`
entries in the sidebar. `navigation.global.anchors`, `navbar.links` and
`navbar.primary` → top navigation links: `navigation.links` in `developerhub.yaml`, at
most four (see [Branding](#branding)).
Languages → ask (one documentation per language is DeveloperHub's manual
translation model). Files not in the navigation → ask (default: hidden pages, but
not `AGENTS.md`, `README.md` and other repository files).

**Frontmatter.** `title`, `description`, `sidebarTitle` → `index_title`, `keywords`;
`icon` + `iconType` → the nav entry's `icon:` (`regular` → `far:`, `brands` →
`fab:`); `hidden`, `noindex` → `listed: false`; `url` (an external link page) → a nav
link; `openapi: 'GET /path'` or `api:` marks a generated endpoint page: migrate the
spec as an API reference, not the page, unless it holds hand-written prose; `mode`,
`tag`, `og:*` dropped.

| Mintlify | DeveloperHub |
|---|---|
| `<Note>`, `<Info>`, `<Callout>` | callout `info` |
| `<Tip>`, `<Check>` | callout `success` |
| `<Warning>` | callout `warning` |
| `<Danger>` | callout `error` |
| `<Accordion title>`, `<AccordionGroup>`, `<Expandable title>` | accordion |
| `<Tabs>` + `<Tab title>` | tabs |
| `<CodeGroup>` + fences (`` ```bash npm `` : the label follows the language) | code group |
| `<RequestExample>`, `<ResponseExample>` | their code, unwrapped |
| `<Steps>` + `<Step title>` | ordered list steps |
| `<Card title icon href>`, `<CardGroup cols>`, `<Columns>`, `<Tiles>` | cards |
| `<Frame caption>` around an image | image with caption |
| `<ParamField path\|query\|body\|header type required default>`, `<ResponseField name type required>` (+ nested `<Expandable>`) | field table |
| `<Icon icon iconType>` | icon |
| `<Badge>` | badge |
| `<Tooltip tip>` | its text |
| `<Update label description>` (changelog) | one changelog post per update |
| `<Latex>` | math |
| `<Tree>`, `<Color>`, `<Panel>`, `<Banner>`, `<View>`, custom snippet components | unwrapped, content kept, logged |
| `import X from '/snippets/x.mdx'` + `<X prop="v" />` | synced block (props → variables) or inline |
| `export const` values | inlined, or variables |
| `` ```js filename.js lines highlight={1-3} wrap `` | `title="filename.js"`, `showLineNumbers=true`, `highlightLines="1-3"` |

## ReadMe

**Content.** A ReadMe export, an `rdme`-synced folder, or a ReadMe Git-backed repo:
`docs/<Category>/<page>.md` with an `_order.yaml` in each folder, plus `reference/`,
`recipes/`, `custom_pages/` and spec files.

**Navigation.** Categories (folders, or `category` frontmatter) are categories, or
documentations when the site has distinct sections (Guides, API Reference, Recipes).
`_order.yaml` lists the slugs in order. `parentDoc` makes a child page. ReadMe
versions arrive as separate folders or exports → versions.

**Frontmatter.** `title`, `excerpt` → `description`, `hidden` → `listed: false`,
`metadata.title` / `description` / `keywords`; `deprecated` → a warning callout at
the top if the customer wants it; `link.url` → a nav link; `api.file` +
`api.operationId` marks an endpoint page generated from a spec (the spec becomes the
API reference; ask about hand-written prose on those pages).

| ReadMe | DeveloperHub |
|---|---|
| `> 📘 Title` / `> 👍 Title` / `> 🚧 Title` / `> ❗️ Title` (blockquote that starts with that emoji) | callout `info` / `success` / `warning` / `error`, the rest of the first line as the title |
| `<Callout icon="…" theme="info\|okay\|warn\|error\|default">` | callout (`okay` → `success`, `warn` → `warning`, `default` → `info`) |
| `[block:callout]{json}[/block]` and other legacy `[block:*]` JSON blocks (`code`, `image`, `parameters`, `html`, `embed`, `api-header`) | parse the JSON: callout, code group, image, table, html, video, `##` heading |
| several fences with no blank line between them | code group, labels from the text after each language |
| `<Tabs>` + `<Tab title>` | tabs |
| `<Accordion title icon>` | accordion |
| `<Cards columns>` + `<Card title href icon>` | cards |
| `<Columns>` + `<Column>` | stacked |
| `<Image src align width caption />` | image |
| `<Embed url>` | video or `{% html %}` iframe |
| `<HTMLBlock>{`…`}</HTMLBlock>` | `{% html %}` |
| `<Glossary>term</Glossary>`, `<<glossary:term>>` | `{% glossary term="term" /%}` |
| `<<variable>>` | `%variable%` or a visible placeholder (ask) |
| `<Recipe>` | a link |

The ReadMe changelog becomes a DeveloperHub changelog, one post per entry, dated from
the entry.

## VitePress and VuePress

**Content.** The folder holding `.vitepress/` (or `.vuepress/`); `public/` serves
files from the site root.

**Navigation.** `themeConfig.sidebar`: one list, or an object keyed by path prefix
(`'/guide/': [...]`, `'/api/': [...]`): one documentation per key. Items are
`{ text, link, items, collapsed }`. `themeConfig.nav` gives the documentation order
and top navigation links. `cleanUrls` decides whether old URLs end in `.html`.
Languages: `locales` in the config and `/<locale>/` folders.

| VitePress / VuePress | DeveloperHub |
|---|---|
| `::: info`, `::: tip`, `::: warning`, `::: danger` (optional title after the type) | callout `info` / `success` / `warning` / `error` |
| `::: details Title` | accordion |
| `> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]` | callout |
| `::: code-group` + fences `` ```sh [npm] `` | code group |
| `` ```js{4,6-8} ``, `// [!code highlight]`, `// [!code ++]` / `--`, `:line-numbers` | annotations or `diff` |
| `<<< @/snippets/file.js{2}` | fence with the file inlined |
| `<!--@include: ./part.md-->` | include |
| `[[toc]]` | removed |
| `layout: home` + `hero` + `features` | landing page: features → cards |
| Vue components, `{{ $frontmatter.x }}`, `v-for` | rendered statically or unwrapped; logged |
| VuePress `<CodeGroup>` + `<CodeGroupItem title>` | code group |

## Starlight

**Content.** `src/content/docs/` (`.md`, `.mdx`, `.mdoc`). Languages:
`src/content/docs/<locale>/`.

**Navigation.** `sidebar:` in the `starlight({...})` call of `astro.config.*`:
`{ label, items: [...] }`, `{ label, autogenerate: { directory } }`, `'slug'`,
`{ slug }`, `{ label, link }`. Without it, the file tree. Frontmatter
`sidebar: { label, order, hidden, badge }` adjusts entries. Top-level groups become
categories, or documentations when the site splits into topics (a topics plugin, or
groups that each read as a product).

| Starlight | DeveloperHub |
|---|---|
| `:::note`, `:::tip`, `:::caution`, `:::danger` (`:::tip[Title]`), `<Aside type title>` | callout `info` / `success` / `warning` / `error` |
| `<Tabs syncKey>` + `<TabItem label icon>` | tabs or code group |
| `<Steps>` around an ordered list | the list itself |
| `<Card title icon>`, `<CardGrid>`, `<LinkCard title href description>` | cards |
| `<Badge text variant>` | badge |
| `<FileTree>` | a plain fence holding the tree |
| `<Code code lang title>` | fence |
| `title="x"`, `{2-3}`, `ins={4}`, `del={5}`, `frame="terminal"` on fences | annotations or `diff` |
| `template: splash` + `hero` | landing page content |

## Nextra

**Content.** `pages/` (Nextra 2 and 3) or `content/` (Nextra 4), `.md` and `.mdx`.

**Navigation.** A `_meta.json` / `_meta.js` / `_meta.ts` per folder: its keys are the
file and folder names in order; a value is a title, or an object with `title`,
`type` (`'page'` at the top level is a navbar tab, so a documentation; `'separator'`;
`'menu'`), `display: 'hidden'`, `href`. `'---'` keys are separators.

| Nextra | DeveloperHub |
|---|---|
| `<Callout type="info\|warning\|error\|default" emoji>` | callout (`default` → `info`) |
| GitHub alerts `> [!NOTE]` | callout |
| `<Tabs items={['npm', 'yarn']}>` + `<Tabs.Tab>` (or `<Tab>`) | tabs or code group, labels from `items` |

**Navigation.** `_sidebar.md` (nested lists of links; one per folder with

| Docsify | DeveloperHub |
|---|---|

| `?> text` | callout `info` |

## mdBook

**Content.** `src/`. **Navigation.** `src/SUMMARY.md`: prefix chapters (unnumbered

| mdBook | DeveloperHub |

## Hugo

**Content.** `content/`. A folder's `_index.md` is the section page (a parent page,
or the documentation's first page). Page bundles keep images beside `index.md`.
Frontmatter may be YAML (`---`) or TOML (`+++`).

**Navigation.** `weight` frontmatter (then title) orders pages; `linkTitle` →
`index_title`; `[[menu.main]]` in the config → top navigation; top-level sections of
a docs theme (Docsy) → documentations; `toc_hide`, `hidden` → `listed: false`.
Languages: `content/<lang>/` or `page.<lang>.md`.

**Shortcodes must all go.** Read any custom one in `layouts/shortcodes/` to see what
it renders.

| Hugo | DeveloperHub |
|---|---|
| `{{% alert title color %}}` (Docsy), `{{< callout type >}}` (Hextra), `{{< hint info >}}` (Hugo Book), `{{% notice note %}}` (Relearn) | callout |
| `{{< tabpane >}}` + `{{< tab header lang >}}` (Docsy), `{{< tabs >}}` + `{{< tab >}}` | tabs or code group |
| `{{< details title >}}`, `{{% expand %}}` | accordion |
| `{{< cards >}}` + `{{< card link title >}}` | cards |
| `{{% steps %}}` with `###` headings (Hextra) | ordered list steps |
| `{{< highlight go "linenos=table,hl_lines=8" >}}` | fence |
| `{{< ref "x.md" >}}`, `{{< relref >}}` | relative `.md` link |
| `{{< figure src caption >}}`, `{{< youtube id >}}`, `{{< vimeo id >}}` | image, video |
| `{{< readfile >}}`, `{{% include %}}` | include |
| `{{< param "x" >}}`, `{{ .Site.Params.x }}` | `%X%` variables |

## Antora and AsciiDoc

**Content.** `antora.yml` per component (`name`, `version`, `nav:`);
`modules/<module>/pages/*.adoc`, `images/`, `partials/`, `examples/`. The playbook
(`antora-playbook.yml`) lists the repositories and branches.

**Navigation.** `nav.adoc` files: nested `* xref:page.adoc[Title]` lists; `.Title`
lines are categories. Components are documentations (or projects: ask); each
component version (a branch or tag) is a version.

**Converting AsciiDoc.** With both tools available:
`asciidoctor -S safe -b docbook5 -o - page.adoc | pandoc -f docbook -t gfm --wrap=none`
(`-S safe` keeps `include::` from reading files outside the docs, which would end up
in public pages),
then fix what remains.

| `[source,java]` + `----` block; `.Title` above it | fence with `title` |
| `include::partial$x.adoc[]`, `include::example$x.java[tag=x]` | include, or a fence with the file |
| `xref:page.adoc#anchor[text]`, `<<anchor,text>>` | links |

| `ifdef::`, `ifeval::` | the branch the published site showed |

## Fern

**Content.** `fern/`; pages are `.mdx`. **Navigation.** `fern/docs.yml`:
`navigation:` lists `- section: Title` (`contents:` nested), `- page: Title` with
`path:`, `- api: API Reference` (generated from a spec), `- link: Title` with `href:`.
`tabs:` with `navigation: - tab: x` → documentations. `versions:` (each with its own
`path:` yml) → versions.

Components are close to Mintlify's: `<Note>`, `<Info>`, `<Tip>`, `<Warning>`,
`<Error>`, `<Success>`, `<Check>`, `<Callout intent>` → callout; `<Steps>` (with
`###` headings) → ordered list steps; `<Tabs>` + `<Tab title>` → tabs;
`<CodeBlocks>` + `<CodeBlock title>` → code group; `<Accordion>`,
`<AccordionGroup>` → accordion; `<Cards>`, `<Card title icon href>` → cards;
`<ParamField>` → field table; `<EndpointRequestSnippet>`,
`<EndpointSchemaSnippet>` → removed, with a link to the API reference. The API is an
OpenAPI file under `fern/` or a Fern Definition; a Fern Definition needs converting to
OpenAPI with Fern's own CLI (the customer's tool: ask before running it).

## Redocly

**Content.** Markdown pages with Markdoc tags; `redocly.yaml` (navbar, theme),
`sidebars.yaml` per folder.

**Navigation.** `sidebars.yaml`: `- page: x.md` (with `label`), `- group: Title` +
`items:` (a group with `page:` is a parent page), `- separator: Title`,
`- href: …` + `label`, `- label: Text`. Navbar items → documentations.

**Redocly's tags look like DeveloperHub's but are other tags.** Rename every one:

| Redocly | DeveloperHub |
|---|---|
| `{% admonition type="info\|success\|warning\|danger" name="Title" %}` | callout, `name` → `title`, `danger` → `error` |
| `{% tabs %}` + `{% tab label="x" %}` | tabs, `label` → `title` |
| `{% partial file="…" variables={…} /%}` | synced block with variables, or inline |
| `{% cards %}` + `{% card title="x" to="./x.md" %}body{% /card %}` | cards, `to` → `link`, body → `text`, self-closing |
| `{% code-snippet file="…" %}` | fence with the file inlined |
| `{% img src="…" %}` | image |
| `{% diagram file="…" type="mermaid" /%}`, mermaid fences | diagrams (read the file it points to) |
| `{% if %}`, `{% $frontmatter.x %}`, `{% $env.x %}` | resolved, or variables |
| `{% json-schema %}`, `{% openapi-code-sample %}`, other API tags | removed, logged, linked to the API reference |

Specs under `openapi/` become API references; a multi-file spec must be bundled into
one file first (Redocly's CLI does this: ask before running it).
